# OfferCat 前端答辩资料

## 一、项目概述

### 1.1 项目定位

**OfferCat** 是一款面向求职者的智能化职业成长助手应用，通过 **AI技术 + 数据可视化** 帮助用户进行职业规划、简历优化和面试准备。

### 1.2 核心功能模块

| 模块 | 功能描述 | 技术亮点 |
|------|----------|----------|
| **AI助手** | 智能问答、模拟面试、简历分析 | 多轮对话、语音播报、限时作答 |
| **星图系统** | 职业路径可视化、专业关联图谱 | Three.js 3D渲染、超边图算法 |
| **成长档案** | 能力雷达图、趋势分析、AI诊断 | 数据可视化、动态图表 |
| **简历工坊** | 在线简历制作、附件管理 | 模块化表单、实时预览 |
| **论坛社区** | 求职经验分享、问答互动 | 社交功能、内容管理 |

## 二、技术选型与理由

### 2.1 主框架：uni-app + Vue 2

**选型理由：**

| 维度 | 说明 |
|------|------|
| **跨平台能力** | 一套代码编译为 Android/iOS 原生应用，降低开发成本 |
| **生态成熟度** | uni-app 社区活跃，插件丰富，问题解决方案多 |
| **原生性能** | 编译为原生渲染，性能优于 WebView 方案 |
| **开发效率** | Vue 语法 + 丰富的组件库，快速迭代 |

### 2.2 星图模块：Vue 3 + Vite + Three.js

**选型理由：**

| 维度 | 说明 |
|------|------|
| **Vue 3 Composition API** | 更好的逻辑复用、TypeScript 支持 |
| **Vite 极速构建** | 开发体验好，HMR 秒级响应 |
| **Three.js 3D渲染** | 实现星系可视化效果，视觉冲击力强 |
| **WebView 隔离** | 独立模块不影响主应用稳定性 |

### 2.3 技术栈对比分析

| 方案 | 优点 | 缺点 | 最终选择 |
|------|------|------|----------|
| React Native | 原生性能好 | 学习成本高、生态不如 uni-app | ❌ |
| Flutter | 性能优秀、UI一致 | 包体积大、Dart语言小众 | ❌ |
| uni-app | 跨平台成熟、Vue生态 | 部分原生能力需插件 | ✅ |
| 纯 H5 | 开发简单 | 性能差、无法上架应用商店 | ❌ |

### 3.2 双模块架构设计

**设计思路：**

1. **主应用**：承载核心业务逻辑，保证稳定性
2. **星图模块**：独立开发、独立部署、独立迭代
3. **WebView桥接**：通过 `postMessage` 实现双向通信

**架构优势：**

| 优势 | 说明 |
|------|------|
| 技术隔离 | Vue 2 与 Vue 3 共存，互不影响 |
| 独立迭代 | 星图功能可单独更新，无需重新发版 |
| 性能优化 | WebView 隔离，避免 3D 渲染影响主应用 |
| 团队协作 | 前后端可并行开发，提高效率 |

## 六、答辩问答准备

### Q1：为什么选择 uni-app 而不是 React Native 或 Flutter？

**回答要点：**

1. **团队技术栈**：团队熟悉 Vue，学习成本低
2. **跨平台成熟度**：uni-app 国内生态成熟，文档完善
3. **开发效率**：一套代码多端运行，快速迭代
4. **原生能力**：通过插件桥接原生能力，满足需求
5. **社区支持**：DCloud 官方维护，问题解决快

### Q2：星图模块为什么单独用 Vue 3 开发？

**回答要点：**

1. **技术需求**：Three.js + TypeScript 需要现代前端工具链
2. **性能考虑**：3D 渲染需要独立线程，避免阻塞主应用
3. **独立迭代**：星图功能复杂，需要独立开发和测试
4. **Vite 优势**：开发体验好，构建速度快
5. **Composition API**：逻辑复用更方便，代码更清晰

### Q3：如何解决 WebView 缓存问题？

**回答要点：**

1. **版本号机制**：静态资源 URL 添加 `?v=版本号` 参数
2. **固定文件名**：入口文件名固定，避免 hash 变化
3. **构建配置**：Vite 配置 `entryFileNames` 固定输出
4. **同步机制**：主应用和星图模块版本号保持同步

### Q4：星图的 3D 渲染性能如何优化？

**回答要点：**

1. **LOD 细节层次**：远处节点降低渲染精度
2. **实例化渲染**：相同几何体使用 InstancedMesh
3. **视锥剔除**：只渲染可见区域
4. **纹理缓存**：节点纹理预生成并缓存
5. **后处理优化**：Bloom 效果参数调优

### Q5：如何保证 AI 对话的流畅性？

**回答要点：**

1. **流式响应**：SSE 实现逐字输出
2. **消息队列**：保证消息顺序正确
3. **自动滚动**：新消息自动滚动到底部
4. **状态管理**：会话状态独立管理
5. **错误重试**：网络异常自动重试

### Q6：项目的难点和解决方案？

**回答要点：**

| 难点 | 解决方案 |
|------|----------|
| 3D 星图性能 | 实例化渲染 + LOD + 视锥剔除 |
| WebView 通信 | postMessage 双向桥接 |
| 缓存更新 | 版本号参数 + 固定文件名 |
| 深色模式 | CSS 变量 + 动态主题切换 |
| 多端适配 | uni-app 条件编译 |

### Q7：项目的可扩展性如何？

**回答要点：**

1. **模块化设计**：功能模块独立，易于扩展
2. **API 层封装**：统一请求处理，便于维护
3. **组件复用**：公共组件抽离，提高效率
4. **配置化**：主题、API 地址等可配置
5. **子包机制**：按需加载，减少包体积
